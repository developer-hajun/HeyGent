# docs 작성 규약

루트 `docs`는 `S14P31E105` 저장소의 공용 협업 문서 공간입니다.
문서 기록은 항상 이 폴더를 기준으로 통일합니다.

## 기본 원칙

- 기본 기록 시점은 PR 생성 시점입니다.
- 같은 PR에 후속 `push`가 생기더라도 단순 오타 수정이나 사소한 정리는 생략할 수 있습니다.
- 리뷰 대응, 구현 방향 변경, 테스트 상태 변경처럼 공유 가치가 있는 후속 `push`는 새 로그를 추가합니다.
- 로그 내용은 PR 본문에 넣을 정도의 정보면 충분합니다.
- 작성자는 기본적으로 `git config user.name` 값을 사용합니다.
- `git config user.name` 값을 확인할 수 없으면 임시로 `unknown` 폴더를 사용합니다.

## 폴더 구조

```text
docs/
  AGENTS.md
  README.md
  logs/
    YYYY-MM-DD-day/
      <git-user.name>/
        001-작업-요약.md
        002-작업-요약.md
  decisions/
    YYYY-MM-DD-주제-요약.md
  handoffs/
    YYYY-MM-DD-작성자.md
```

- 날짜 폴더는 `2026-04-24-thu` 형식을 사용합니다.
- 요일은 `mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `sun` 중 하나를 사용합니다.
- 작성자 폴더는 `git config user.name` 값을 그대로 사용합니다.

## 로그 파일명 규칙

- 로그 파일명은 시간 대신 인덱스를 사용합니다.
- 형식: `001-작업-요약.md`
- 같은 날짜와 같은 작성자 폴더 안에서만 순번을 올립니다.
- 시작 번호는 `001`이고, 다음 파일은 `002`, `003` 순으로 작성합니다.

## 로그 작성 기준

- 새 PR을 만들 때는 반드시 로그 1개를 작성합니다.
- 같은 PR에 대해 공유 가치가 있는 후속 `push`가 있으면 새 인덱스 로그를 추가합니다.
- 같은 날 같은 작성자가 여러 PR을 다루더라도, 폴더 안에서는 인덱스를 계속 증가시킵니다.
- 장기 설계 합의가 생기면 로그에만 남기지 말고 `docs/decisions/`에 별도 문서를 만듭니다.
- 다음 작업자가 바로 이어받아야 하는 상태 정리는 `docs/handoffs/`에 작성합니다.

## 로그 템플릿

```md
# 작업 로그

## 날짜

2026-04-24

## 작성자

theundergroundt

## 관련 브랜치 / PR

- 브랜치: BE-feat/taskrun-state
- PR: #12

## 작업 목적

- 이번 PR 또는 push에서 공유해야 할 목적

## 변경 요약

- 무엇을 만들었는지
- 무엇을 수정했는지
- 무엇을 제거했는지

## 주요 파일

- `app/...`
- `tests/...`

## 테스트 / 확인

- 실행한 테스트
- 아직 확인 못 한 내용

## 결정 / 이슈

- 리뷰어가 알아야 할 판단
- 남아 있는 리스크나 제약

## 다음 단계

- 다음 push 또는 다음 작업자가 이어갈 내용
```

## 작성 원칙

- 짧고 사실 중심으로 작성합니다.
- 코드 전문이나 긴 터미널 출력은 넣지 않습니다.
- PR 설명에 적을 정도의 핵심만 남깁니다.
- 민감 정보와 개인 환경값은 적지 않습니다.
