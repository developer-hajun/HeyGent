## 작업 목적

- 사용자가 기존 작업을 채팅 실행에 명시적으로 붙였을 때 TaskRun과 WorkItem 실행 이력이 연결되도록 보강합니다.

## 변경 요약

- HTTP 세션 메시지 생성 경로에서 `workId` 입력을 검증하고 작업 컨텍스트를 TaskRun 입력에 추가했습니다.
- WebSocket 세션 메시지 생성 경로에서도 같은 `workId` 검증과 작업 컨텍스트 주입을 적용했습니다.
- 연결된 작업 실행은 시작 시 `work_runs`에 기록하고, TaskRun 종료 결과의 disposition을 WorkItem 상태에 반영합니다.
- 실행 중 예외가 발생하면 연결된 작업 실행 이력을 `FAILED`로 갱신합니다.

## 주요 파일

- `AI/app/api/http/sessions.py`
- `AI/app/api/ws/commands.py`

## 테스트 / 확인

- `python -m compileall app\api\http\sessions.py app\api\ws\commands.py`
- `python -m pytest tests\api\test_tasks_runtime.py tests\api\test_ws_commands.py`

## 결정 / 이슈

- 작업 연결은 자동 추론이 아니라 요청 payload의 명시적 `workId`만 처리합니다.
- `workId`가 다른 세션의 작업을 가리키면 실행을 막습니다.
