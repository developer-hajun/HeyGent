# 작업 목적

채팅 작업 모드에서 사용자가 세션 에이전트에게 맡기라고 요청했을 때 내부 임시 worker가 아니라 작업 보드에 보이는 하위 작업과 실제 세션 에이전트 실행으로 이어지게 한다.

# 변경 요약

- CEO 작업 실행 중 세션 에이전트에게 하위 작업을 만들고 실행하는 `session_agent_task` runtime tool을 추가했다.
- CEO 프롬프트에서 세션 에이전트 배정과 내부 worker 병렬 처리를 분리했다.
- CEO 작업 컨텍스트에 현재 세션 에이전트 후보를 넣어 모델이 실제 프로필 ID로 하위 작업을 만들 수 있게 했다.
- 하위 작업 실행 시 해당 세션 에이전트 프로필과 지침 묶음을 실행 컨텍스트로 전달한다.
- 작업 모드 입력에 정확한 `TASK-숫자`가 들어오면 새 작업을 만들지 않고 기존 작업 조회 흐름으로 처리하게 했다.
- 외부 도구 결과에 null 문자가 섞여도 durable/session JSONB 저장이 실패하지 않도록 저장 전 정리했다.

# 결정, 이슈, 리스크

- `worker.default`는 보드 담당자나 세션 에이전트 배정에는 쓰지 않고, 명시적인 내부 병렬 처리 요청에만 쓰도록 프롬프트와 도구 설명을 좁혔다.
- 이전 실테스트 중 실패한 `TASK-4`, `TASK-6`, `TASK-9`는 기존 실행 이력으로 남아 있다.
- 장시간 웹 조사 작업은 모델 반복 횟수와 외부 검색 결과 품질에 영향을 받는다.
