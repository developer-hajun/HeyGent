## 작업 목적

- 작업 보드 프론트 구조를 기능 단위 폴더로 정리하고, 채팅 입력에서 작업 모드를 켤 수 있게 연결합니다.

## 변경 요약

- 작업 보드 구현을 `sessionWorkspace/work` 아래 `board`, `model`, `detail`, `inbox` 구조로 이동했습니다.
- 기존 `sessionWorkspace/issueBoard` 경로는 새 작업 보드 구현을 다시 내보내는 호환 경로로 남겼습니다.
- 작업 API, 타입, store, 실시간 이벤트 정규화 파일을 추가했습니다.
- 채팅 입력의 `+` 메뉴에 작업 모드 토글을 추가하고, 기존 세션에서 작업 모드 전송 시 새 작업 생성 API를 호출하도록 연결했습니다.
- 채팅 입력의 `+` 메뉴에 기존 작업 선택을 추가하고, 선택한 작업의 `workId`를 채팅 실행 payload에 붙이도록 연결했습니다.
- 작업 보드 상태 표시를 서버의 7개 작업 상태에 맞추고 우선순위 표시는 제거했습니다.

## 결정 / 이슈

- 새 대화 화면은 아직 세션 ID가 없으므로 작업 모드 실행을 막고 안내 문구를 보여줍니다.
- 작업 목록/생성은 REST 응답과 store로 반영하며, 작업 전용 WebSocket 이벤트 연결은 후속 작업으로 남아 있습니다.
