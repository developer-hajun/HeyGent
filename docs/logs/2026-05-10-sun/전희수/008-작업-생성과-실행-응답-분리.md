## 작업 목적

- 작업 모드 입력이 긴 실행 때문에 생성 단계에서 타임아웃나지 않도록 합니다.
- 작업 생성과 실제 실행 시작을 분리해 채팅 화면에 빠르게 사용자 입력과 실행 상태가 나타나게 합니다.

## 변경 요약

- 작업 생성 요청에 `startExecution` 옵션을 추가했습니다.
- `startExecution=false`이면 작업만 만들고 즉시 응답하도록 했습니다.
- 프론트 작업 모드는 작업을 먼저 만든 뒤, 기존 실시간 메시지 명령으로 해당 작업 실행을 시작합니다.
- 생성된 작업 번호와 담당자 정보가 채팅 메시지 실행 컨텍스트에 이어지도록 했습니다.

## 결정, 이슈, 리스크

- 작업 생성 REST는 빠르게 끝나고, TaskRun 시작은 실시간 메시지 경로를 사용합니다.
- 실시간 연결이 없으면 작업 모드 실행을 시작하지 않고 연결 오류를 보여줍니다.

## 다음 단계

- 작업 보드에서 담당자를 바꾼 뒤 실행 컨텍스트에 반영되는지 확인합니다.
