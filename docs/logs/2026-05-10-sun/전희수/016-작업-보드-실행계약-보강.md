## 작업 목적

- 작업 보드의 실행, 라벨, 관계, 댓글, 삭제 흐름을 실제 API와 화면에서 이어지게 보강한다.
- 작업 보드 프론트 파일이 길어진 부분을 역할별 파일로 나눠 유지보수성을 높인다.

## 변경 요약

- 작업 라벨, 관계, 실행 생성/취소, 댓글 삭제, 작업 삭제 API 계약과 저장소 구현을 추가했다.
- 작업 실행 종료 시 LLM이 명시적 처리 결과를 남기도록 도구와 프롬프트, 상태 반영 로직을 연결했다.
- 작업 보드에서 서버 라벨, 실행 버튼, 삭제 버튼, 관계 추가, 실시간 갱신 이벤트를 사용할 수 있게 했다.
- 보드 실행 버튼은 서버 실행을 즉시 만들지 않고 채팅 입력에 작업 배지와 기본 문구를 채우도록 맞췄다.
- `IssueBoardPanel.tsx`의 변환/필터/저장 유틸과 관계 탭 UI를 별도 파일로 분리했다.
- 실행 없이 생성한 작업은 `todo` 상태로 남도록 보정했다.

## 결정 / 이슈

- 라벨 삭제는 기존 작업 연결을 제거하는 방식으로 처리한다.
- 작업만 생성하는 요청은 실행 중 상태가 아니라 `todo` 상태로 남긴다.
- 현재 API 키 등록 오버레이는 별도 설정 상태이며, 나중에 닫은 뒤 작업 보드 UI를 확인했다.
