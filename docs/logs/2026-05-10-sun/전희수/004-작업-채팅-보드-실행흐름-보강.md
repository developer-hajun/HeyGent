## 작업 목적

- 작업 모드에서 만든 작업이 실제 채팅 메시지 흐름에 남도록 연결합니다.
- 기존 작업을 선택해 보낸 메시지가 작업 번호와 함께 표시되고 실행 이력에 붙도록 보강합니다.
- 보드 상세의 상태 변경과 댓글이 서버 데이터로 저장되고 다시 조회되도록 연결합니다.

## 변경 요약

- 작업 생성 API가 세션 메시지 생성 경로를 함께 사용하도록 바꿔 사용자 입력과 assistant 응답을 대화 타임라인에 저장했습니다.
- 세션 메시지 metadata에 작업 ID, 작업 번호, 제목, 담당자 정보를 저장하고 프론트 채팅 말풍선에 작업 배지를 표시했습니다.
- 기존 작업 선택 전송 시 작업 정보를 `inputPayload`에 함께 넣어 낙관 메시지와 저장 메시지 모두 같은 배지로 보이게 했습니다.
- 보드 상세에서 상태 변경, 댓글 추가, 댓글 재조회가 서버 API와 연결되도록 프론트 store와 API 함수를 추가했습니다.
- 작업 라벨 교체 API가 기존 연결을 제거한 뒤 새 라벨을 연결하도록 정리했습니다.

## 결정, 이슈, 리스크

- 작업 모드 생성은 지금도 HTTP 요청 안에서 실행 완료까지 기다리는 구조입니다. 긴 실행은 이후 비동기 시작 응답으로 분리하는 것이 좋습니다.
- 작업 전용 WebSocket 이벤트 토픽은 아직 별도 구현되지 않았습니다. 이번 보강은 REST 명령 성공 후 store 갱신과 재조회로 사용자 눈에 보이는 정합성을 먼저 맞췄습니다.
- 작업 상세의 제목/본문 편집, 담당자/라벨 편집, 하위 작업/차단 관계 표시는 남은 구현 범위입니다.

## 다음 단계

- 작업 전용 실시간 이벤트 구독을 추가해 보드 갱신 기준을 WebSocket으로 이동합니다.
- 작업 상세 제목/본문을 읽기 모드와 클릭 편집 모드로 분리합니다.
- 담당자, 라벨, 하위 작업, 차단 관계 명령을 서버 API와 연결합니다.
