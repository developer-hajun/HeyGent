## 작업 목적

기본 에이전트 전체 추가 흐름에서 CEO가 세션 에이전트 후보를 보고 수행 가능한 담당자에게 작업을 넘기도록 라우팅 기준을 보강한다.

## 변경 요약

- 기본 생성 버튼 문구를 `기본 에이전트 모두 추가`로 바꿔 단일 템플릿 선택과 구분했다.
- CEO 지침에서 수행 가능한 등록 에이전트가 있으면 정보 조회, 검토, 구현, 테스트 작업을 우선 세션 에이전트에게 맡기도록 강화했다.
- 런타임 프롬프트와 `session_agent_task` 도구 설명에서 CEO가 웹/파일/브라우저 도구를 직접 잡기 전에 세션 에이전트 작업을 만들도록 명시했다.
- 전체 기본 에이전트가 들어간 세션에서 K-에이전트가 지하철 분실물 안내 작업을 맡고 K 스킬 목록을 받는지 확인했다.

## 테스트 또는 확인 내용

- `AI\.venv\Scripts\python.exe -m pytest AI\tests\domain\test_agent_templates.py AI\tests\domain\test_skill_driven_work_tracking.py AI\tests\test_model_loop_contract.py`
- `npm run build`
- `docker compose up -d --build ai frontend`
- `GET /ai/api/v1/ready`
- 개발 로그인 후 브라우저에서 새 세션을 만들고 `기본 에이전트 모두 추가` 버튼을 눌러 개발 에이전트, QA 에이전트, UX 디자이너, K-에이전트가 모두 들어온 것을 확인했다.
- 같은 세션에서 지하철 분실물 사용자 입력을 보내 CEO TaskRun이 K-에이전트 TaskRun을 생성했고, K-에이전트 TaskRun에 `subway-lost-property` 포함 K 스킬 16개가 주입된 것을 확인했다.

## 결정, 이슈, 리스크

- 단일 K-에이전트 카드 선택 테스트와 전체 기본 에이전트 추가 테스트가 헷갈리지 않도록 버튼 문구를 분리했다.
- Firecrawl 직접 설정이 없어 일부 scrape가 비어도 hosted web search와 에이전트 실행은 완료됐다.
