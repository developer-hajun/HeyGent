## 목적

- AI 서버의 Postgres/Redis 기반 TaskRun 오케스트레이션과 realtime WebSocket 연결 정책을 이어서 작업할 수 있게 현재 구현 상태를 정리한다.
- 프론트가 AI WebSocket에 직접 연결하고, AI 서버가 backend에 토큰 검증을 요청하는 흐름을 기준으로 인수인계한다.

## 현재 확정된 연결 정책

- 프론트는 AI 서버 WebSocket에 직접 연결한다.
- 제품용 AI WebSocket 경로는 `/ai/api/v1/realtime/user/ws`다.
- backend API의 `/api/v1`과 AI API의 `/ai/api/v1`을 분리해 배포 라우팅과 로그 구분을 쉽게 한다.
- 브라우저 WebSocket은 임의 Authorization header를 넣기 어렵기 때문에 연결 직후 첫 메시지로 인증한다.
- 첫 인증 메시지는 `{ "type": "auth.start", "accessToken": "..." }` 형식을 사용한다.
- AI 서버는 accessToken을 직접 신뢰하지 않고 backend의 내부 인증 검증 API에 확인을 요청한다.
- backend 검증 결과의 `userId`, `workspaceKey`, `scope`만 실행 context와 구독 권한 판단에 사용한다.
- client가 보낸 `userId`나 임의 session 정보는 신뢰하지 않는다.

## 현재 구현 상태

- AI 기본 API prefix는 `/ai/api/v1`이다.
- AI WebSocket gateway는 문서 계약의 `type` 메시지를 받는다.
  - `auth.start`
  - `ping`
  - `subscribe.task`
  - `subscribe.all`
- 기존 전환기 호환을 위해 `action` 기반 메시지도 아직 수용한다.
  - `auth`
  - `ping`
  - `subscribe`
  - `subscribe_all`
- 프론트 realtime client는 `frontend/src/realtime` 아래에 있다.
- 프론트 realtime client는 `VITE_AI_WS_BASE_URL` 환경변수만 사용하고, 코드에 localhost URL을 하드코딩하지 않는다.
- 프론트 로컬 `.env`에는 `ws://localhost:8000/ai/api/v1/realtime/user/ws`가 들어가 있다.
- 프론트 `.env.example`에도 같은 AI WebSocket 예시 URL을 추가했다.

## 데이터와 런타임 기준

- Postgres는 durable TaskRun anchor, agent session, worker handoff, transcript 같은 장기 기준 데이터를 맡는다.
- Redis는 realtime projection, active lock, recent event, WebSocket connection registry 같은 TTL 기반 런타임 데이터를 맡는다.
- WebSocket은 canonical store가 아니라 realtime transport다.
- reconnect 이후에는 auth를 다시 수행하고, 필요한 TaskRun 구독을 다시 등록해야 한다.
- 유실 복구는 WebSocket 자체가 아니라 HTTP 조회 API와 Redis/Postgres snapshot 조합으로 처리한다.

## 프론트 realtime client 기준

- `createTaskRunSocket`은 WebSocket 연결, 인증 시작, 구독, ping, close를 담당한다.
- `parseTaskRunSocketEvent`는 서버 JSON 문자열을 안전한 이벤트 타입으로 변환한다.
- `subscribeTask`는 `{ type: "subscribe.task", taskRunId }` 메시지를 보낸다.
- `ping`은 `{ type: "ping" }` 메시지를 보낸다.
- `auth.ok`을 받기 전에는 TaskRun 구독을 client 단계에서 막는다.
- 서버 응답은 아직 snake_case 필드를 포함할 수 있어 `subscribed.task_run_id`도 client에서 `taskRunId`로 정규화한다.

## 남은 주의점

- `ai/.env.example`은 이전 정책상 아직 수정하지 않았다. 새 prefix를 완전히 공식화할 때 별도 변경이 필요하다.
- WebSocket auth refresh 만료 처리와 scope 만료 시 강제 재검증은 추가 고도화 대상이다.
- `frontend/src/realtime`은 아직 화면에 본격 연결되지 않았다. 실제 화면 연결 시 active TaskRun 조회와 reconnect 재구독 로직을 함께 붙여야 한다.
- `subscribe.all`은 보안상 서버에서 거부될 수 있으므로 일반 사용자 화면에서는 사용하지 않는 것이 맞다.
