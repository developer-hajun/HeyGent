### 2) 환경변수 확인 (이관 직후)

- `backend` 의 `application-*.yml` 또는 `.env` 에 `ai.internal.token` (= `HEYGENT_INTERNAL_SERVICE_TOKEN`) 이 설정돼 있는지.
- `ai/.env` 의 `HEYGENT_INTERNAL_SERVICE_TOKEN` 이 backend 와 같은 값인지.
- **`ai/.env` 에 `HEYGENT_BACKEND_BRIDGE_AUTH_VERIFY_URL=http://backend:8080/internal/bridge/auth/validate` 가 있어야 함.** 없으면 코드 기본값(127.0.0.1) 으로 폴백해 컨테이너 안에서 backend 를 못 찾고 브릿지 hello 가 `invalid_token` 으로 거절됨. dev 폴더 E2E 검증에서 실제로 한 번 막혀서 추가했음.
- `ai/.env` 의 `HEYGENT_BRIDGE_TOKEN` 은 더 이상 안 읽지만 남아 있어도 무방.

### 3) 검증 시나리오 (로컬)

```powershell
docker compose up -d --build

# 브라우저: http://localhost:5173 → 로그인 → /settings/bridge 또는 좌측 메뉴 "내 PC 브릿지"
# "새 브릿지 연결" → 코드 발급 → 코드 메모

cd bridge
pip install -r requirements.txt
python -m bridge.tray
# GUI: 환경 "로컬" → 페어링 코드 + 디바이스 이름 → "페어링 요청" → "시작"
# 트레이 H 아이콘이 초록색이 되면 연결 성공

# 채팅에서: "whoami 실행해줘" → 본인 윈도우 사용자명 응답
```

### 4) 검증 시나리오 (배포)

위와 동일하되 GUI 에서 "배포" 라디오 선택. backend `https://k14e105.p.ssafy.io/api/v1/bridge/pair`, AI `wss://k14e105.p.ssafy.io/ai/api/v1/internal/bridge/ws`.

체크포인트:
- backend 가 `https://k14e105.p.ssafy.io/api/v1/bridge/pair` 에 routing 되어 있는지 (Nginx Proxy Manager 설정).
- `wss://` 인증서 검증이 Python `websockets` 에서 통과하는지. 통과 안 되면 `ssl_context.check_hostname` 또는 `ssl_context.load_verify_locations(...)` 추가 필요.

## 남아 있는 미확인 / 후속

- 페어링 코드 brute force 방어 (현재 없음): 1차에선 6자리 + TTL 5분 + 1회용으로 충분하다고 봤지만, 실제 운영 들어가면 IP 기반 rate limit 추가 권장.
- WebSocket 메시지 크기 1 MiB 기본 제한 (Python `websockets` + uvicorn): 이번 작업 범위는 아니지만 텍스트 1MB 가 넘는 파일을 도구로 다루기 시작하면 양쪽에서 `max_size` 늘려야 함.
- 브릿지 `.exe` 빌드·배포 흐름: PyInstaller 명령은 README 에 적혀 있지만 자동 업데이트는 없음.
- 디바이스 이름 XSS: frontend 표시는 React 가 escape 해 안전하지만 backend 단에서 길이 제한(현재 60자) 외 특수문자 정책 검토 가능.
- 같은 user 가 다른 PC 에서 페어링 시 첫 PC 의 브릿지가 자동 끊기는지 실제 확인 (코드상으로는 `BridgeSessionManager.register` 가 기존 세션을 close 하지만 실제 close timing 검증 필요).
