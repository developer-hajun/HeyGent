# 에이전트 지침서 (AGENTS)

이 문서는 HeyGent의 `AI` 폴더에서 작업할 때의 공용 정책과 최소 구현 원칙을 정의합니다.

## 정책

- 사용자가 명시적으로 구현 또는 코드 수정을 요청하기 전까지는 파일을 수정하지 않습니다.
- 파일/코드 검색, 읽기, 분석, 구조 검토, 설계/계획 수립, 리팩터링 아이디어 제안은 항상 가능합니다.
- 코드 수정이 허용된 이후에도 변경은 최소·점진적으로 수행합니다.
- 기존 코드 스타일과 패턴을 최대한 존중합니다.
- 불필요한 설정 변경이나 범위 밖 기능 추가는 지양합니다.
- 특정 로컬 경로나 임시 문서를 작업 전제로 고정하지 않습니다.
- 저장소의 현재 코드 구조와 실제 실행 환경을 우선 기준으로 판단합니다.

## 협업 문서화 규칙

- 협업 공유가 필요한 모든 의미 있는 작업 결과는 항상 `docs/...` 아래에 요약 기록합니다.
- 여기서 기록 단위는 파일 저장이나 사소한 수정이 아니라, 기본적으로 `push` 또는 PR 생성/업데이트 시점입니다.
- 하나의 PR에 대해 처음 공유하는 시점에는 반드시 로그를 남기고, 이후에도 리뷰 대응이나 방향 변경이 있으면 다음 로그를 추가합니다.
- 기록 위치, 폴더 구조, 파일명, 템플릿은 `docs/AGENTS.md`를 따릅니다.
- 작성자 구분은 기본적으로 `git config user.name` 값을 사용합니다.
- 장기적으로 유지해야 하는 설계 결정은 `docs/decisions/`에 별도 문서로 승격합니다.
- 다음 작업자에게 바로 넘겨야 하는 내용은 `docs/handoffs/`에 정리합니다.
- 비밀값, 토큰, 민감한 로컬 경로, 불필요한 터미널 원문은 문서에 남기지 않습니다.

## 브랜치명 규칙

- 규칙: `타입/이슈키-설명`
- 예시:
  - `BE-feat/로그인-구현`
  - `BE-fix/CORS-수정`

## 커밋 메시지 규칙

- 규칙: `컴포넌트-작업타입: 설명`
- 실제 커밋 메시지는 공백 포함 형식인 `컴포넌트-작업타입 : 한글 설명`을 사용합니다.
- 설명은 영어가 아니라 한글로 작성합니다.
- 예시:
  - `BE-feat : 로그인 API 구현`
  - `BE-fix : WebMvcConfig CORS 설정 허용`
- 작업타입 유형:
  | **태그** | **설명** |
  | --- | --- |
  | `feat` | 새로운 기능 추가 |
  | `fix` | 버그 및 에러 수정 |
  | `refactor` | 기능 변경 없는 코드 구조 개선 (변수명 변경, 코드 분리 등) |
  | `modify` | **기획 변경**으로 인한 기존 기능/비즈니스 로직 수정 |
  | `docs` | README, 문서 작성 및 수정 |
  | `chore` | 빌드 설정, 패키지 설치 등 코드 외 작업 |
  | `release` | 버전 배포 |
  | `docs` | 문서 작업 |
  | `design` | 디자인 수정 |

## 서브에이전트 규칙

- `subagent depth` 는 **1**로 봅니다.
- subagent 가 또 다른 subagent 를 생성하는 구조는 기본 전제로 두지 않습니다.
- 상위 레벨에서 여러 개의 병렬 세션을 만드는 구조는 허용합니다.

---

## 용어 고정

아래 용어는 코드와 문서에서 그대로 사용합니다.

- `TaskRun`
- `StepRun`
- `Orchestrator`
- `Task Engine`
- `Model Provider`

코드 상의 기본 이름은 유지하고, 필요한 경우 한글 설명은 주석이나 문서에서 보완합니다.

---

## 구현 원칙

- 큰 파일 하나에 모든 코드를 몰아넣지 않습니다.
- 모델 호출은 `Model Provider` 레이어를 통해서만 수행합니다.
- 상태 전이 로직에는 한글 주석을 작성합니다.
- 전반적으로 한글 주석을 충분히 작성합니다.
- `subagent depth = 1` 전제를 유지합니다.
- 현재 단계에서는 완성형 제품 아키텍처를 한 번에 확정하려 하지 않고, 백본 검증에 필요한 최소 구조부터 구현합니다.
- provider / orchestration / execution 책임이 섞이지 않게 유지합니다.

---

## 구조 원칙

- 현재 저장소에 이미 존재하는 폴더와 파일을 우선 활용합니다.
- 로컬 전용 예시 구조나 특정 머신 전용 산출물을 필수 기준으로 강제하지 않습니다.
- 새 파일을 만들 때는 현재 코드베이스의 계층 책임과 이름 규칙을 우선 맞춥니다.
- 환경마다 경로나 실행 방식이 달라질 수 있으므로, 문서와 설정은 가능한 한 환경 변수 중심으로 설명합니다.
