# AGENTS

이 문서는 에이전트 사용 정책과 코드 스타일을 정의합니다.

## 정책

### 기본 원칙

- 사용자가 `코드수정해줘`라고 말하기 전까지는 어떤 파일도 수정하지 않습니다.

### 항상 허용되는 작업

- 파일 및 코드 검색
- 파일 읽기 및 분석
- 설계 및 계획 수립
- 제안서 및 구현 방향 작성
- 성능, 아키텍처, 리팩터링 아이디어 제시

### 코드 수정 허용 트리거

- 사용자가 `코드수정해줘`라고 명시하면 그 시점부터 수정할 수 있습니다.
- 사용자는 수정 범위를 함께 지정할 수 있습니다.
- 예시: `코드수정해줘 src/pages/Impr.tsx`
- 범위를 지정하지 않으면 저장소 전체 수정이 가능하지만, 변경은 최소하고 점진적으로 진행합니다.

### 변경 원칙

- 기존 코드 스타일과 패턴을 우선 따릅니다.
- 불필요한 설정 변경은 하지 않습니다.
- 영향 범위가 큰 변경은 사전 설명과 동의 후 진행합니다.

## 명명 규칙

- 컴포넌트 파일명은 PascalCase로 통일합니다.
- 컴포넌트명은 PascalCase를 사용합니다.
- 훅 이름은 `use`로 시작하는 camelCase를 사용합니다.
- 유틸 함수명은 camelCase를 사용합니다.
- CSS 클래스는 snake_case를 사용합니다.
- CSS Modules에서는 `styles.class_name` 형태로 접근합니다.
- 약어와 축약은 지양하고 의미 중심으로 명명합니다.
- 동일 개념은 프로젝트 전반에서 같은 용어를 사용합니다.
- 재사용 하위 파트가 많아 구조적 구분이 필요하면 BEM 사용을 허용합니다.

## 코드 스타일 규칙

- 포맷은 Prettier 기준을 따릅니다.
- 한 줄 길이는 100자 기준으로 유지합니다.
- 들여쓰기는 공백 2칸을 사용합니다.
- 문자열은 작은따옴표를 사용합니다.
- 세미콜론은 사용하지 않습니다.
- Tailwind 클래스 순서는 자동 정렬 기준을 따릅니다.
- import 경로는 상대경로보다 `@` alias 사용을 우선합니다.
- 환경변수 파일은 커밋하지 않고, 예시 파일만 추적합니다.
- 커밋 시 staged 파일에 대해 `eslint --fix`, `prettier --write`를 실행합니다.

## 브랜치명 규칙

- 규칙: `타입/이슈키-설명`
- 예시: `FE-feat/대시보드-구현`
- 예시: `FE-fix/레이아웃-수정`
- 예시: `FE-chore/프론트-개발환경-구성`

## 커밋 메시지 규칙

- 규칙: `컴포넌트-작업타입 : 설명`
- 예시: `FE-feat : 대시보드 페이지 구현`
- 예시: `FE-fix : 사이드바 접힘 상태 수정`
- 예시: `FE-chore : 프론트 AGENTS 문서 추가`
